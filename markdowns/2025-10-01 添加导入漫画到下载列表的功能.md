# 导入漫画到下载列表的功能与修改总结

## 1. 功能背景
为支持用户将本地或外部来源的压缩包漫画 (ZIP) 导入到应用现有的下载管理体系中，新增 `ImportComicScene` 场景。在该场景中，用户可选择一个 `.zip` 文件，系统自动解析、解压、生成必要的元数据与数据库记录，使其与正常下载完成的漫画条目保持一致，可在“下载”页中查看与阅读。

## 2. 核心流程概述
1. 用户在侧边导航选择“导入漫画”进入 `ImportComicScene`。
2. 点击“选择压缩包”按钮，使用系统文件选择器 (`ACTION_OPEN_DOCUMENT`, MIME `application/zip`) 选择 ZIP 文件。
3. 回调 `onActivityResult` 后启动异步导入任务：
	- 获取文件名，尝试解析 `gid-token` 格式；失败则随机生成。
	- 创建 `DownloadInfo`（初始即标记为已完成）。
	- 通过 `SpiderDen.getGalleryDownloadDir()` 创建漫画存储目录。
	- 首次扫描 ZIP 统计有效图片文件数；重新打开流后逐个解压并按顺序重命名（`%08d` + 扩展名）。
	- 生成并写入 `SpiderInfo` 元数据文件 (`SpiderQueen.SPIDER_INFO_FILENAME`)。
	- 更新 `DownloadInfo` 的总页数 / 已完成数，并写入数据库 `EhDB.putDownloadInfo(downloadInfo)`。
	- 通知 `DownloadManager` 加入下载列表，导航返回“下载”场景。
4. 失败场景会更新提示文本与 Toast 给出原因（目录创建失败 / 无图片 / IO 异常等）。

## 3. gid 与 token 生成与解析规则
| 情况 | 规则 |
|------|------|
| 文件名匹配正则 `(\d+)-(\w+)` | `gid = Long.parseLong(第一组)`；`token = 第二组` |
| 不匹配 | `gid = abs(UUID.randomUUID().getLeastSignificantBits())`；`token = UUID 前 10 字符` |

注意：`token` 采用字母数字与下划线（正则 `\w`），随机生成时为 UUID 字符串片段（保证一定随机性与唯一性）。命名压缩包时可使用例如：`1234567-abc123def4.zip`，以保持跨设备识别的一致性。

## 4. 关键类与文件
| 类 / 文件 | 作用 | 相关修改 |
|-----------|------|----------|
| `ImportComicScene` | 新增的导入漫画场景 | 实现解压、生成元数据、写入数据库、导航下载页 |
| `MainActivity` | 场景注册与导航 | 注册 `ImportComicScene`；移除冗余 `mSceneDelegate`；增强导航方法 |

## 5. 遇到的问题与对应修复
| 问题 | 原因 | 修复措施 |
|------|------|----------|
| “Not register ImportComicScene” 运行时异常 | 静态初始化 & 注册可见性排查，确认已在 `MainActivity` 的静态块注册 | 进行清理构建；确保类加载顺序；无逻辑缺失后问题消失 |
| `SparseArray.size()` 空指针相关异常（疑似） | `MainActivity` 中多余的 `mSceneDelegate` 字段未初始化可能引导错误使用 | 删除 `mSceneDelegate`，直接使用继承的 `StageActivity` 功能 |
| 引用 `Announcer` / `DownloadsScene` 编译报“找不到符号” | 在新增 fallback 调用中缺少 import | 补充 `import com.hippo.scene.Announcer;` 与 `import com.hippo.ehviewer.ui.scene.download.DownloadsScene;` |
| 导入成功后导航失败或异常 | 直接调用导航时可能出现异常 | 包装 try-catch，失败时使用 `startScene(new Announcer(DownloadsScene.class))` 兜底 |
| 视图创建方法命名不正确 | 子类应实现 `onCreateView3` 而非 `onCreateView2` | 改为正确覆盖 `onCreateView3`，保持 ToolbarScene 内容插入流程 |
| 文件名解析失败导致 gid/token 不可用 | 压缩包命名不符合约定 | 增加随机生成回退逻辑，保障流程不被阻断 |

## 6. 当前实现的优点
- 与原生下载体系完全对接：目录结构、`SpiderInfo`、数据库记录、下载管理入口统一。
- 支持文件名直观控制 gid/token，方便二次迁移或同步。
- 解压流程双遍扫描（先统计再写入）避免进度计算混乱。
- 失败路径明确：目录 / IO / 内容校验 全部给出用户层面反馈。
- 具备导航失败兜底，保证导入完成后用户总能进入下载列表。

## 7. 可进一步优化的方向
1. 进度反馈：当前只显示“导入中”与最终结果，可添加实时进度（已解压 / 总页数）。
2. 支持更多压缩格式：如 `.cbz`（实质 ZIP）、`.rar`、`.7z`（需引入第三方库）。
3. 文件过滤策略：忽略缩略图目录、隐藏文件、损坏图片的自动跳过与统计。
4. 尝试从文件内部（如 `info.json`）读取更丰富的元数据（标题、作者、标签）。
5. 去重/合并：导入时检查是否已存在相同 `gid` 或标题的条目，提示合并或跳过。
6. 异步任务替换：使用 `Coroutine` / `WorkManager`（在 Kotlin 迁移后）提高可控性与可取消性。

## 9. 使用简要说明
1. 在侧边栏选择“导入漫画”。
2. 选择一个包含图片的 ZIP 压缩包：支持 jpg/jpeg/png/gif/webp。
3. （可选）压缩包命名含 `gid-token` 结构可复用外部编号，例如：`9876543-xyz123abcd.zip`。
4. 等待导入完成后自动跳转到“下载”页面查看已导入漫画。

## 10. 兼容性与注意事项
- 不处理多级目录结构中的图片（若存在子目录图片需确认是否被识别）。
- 非图片文件将被忽略，不影响流程。
- 若 ZIP 内无有效图片将直接失败并提示。
- 生成的随机 gid 在极少情况下可能与现有条目冲突（可增加冲突检测）。
