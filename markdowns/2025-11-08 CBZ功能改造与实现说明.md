# CBZ 功能改造与实现说明（2025-11-08）

本文档总结本次围绕 CBZ（Comic Book ZIP）支持所进行的功能新增与代码改造，覆盖阅读、转换、自动打包、设置项、字符串本地化与可靠性优化等内容。

## 概述
- 新增对已下载漫画目录下 .cbz 的读取支持（无需解压，直接流式读取图片）
- 下载列表支持按存储形态筛选（仅图片/仅压缩包）与批量转换（图片 ↔ CBZ）
- 高级设置新增“下载完成后自动打包为 CBZ”开关
- 自动打包在下载完成时触发，写入 ComicInfo.xml，并在成功后清理图片
- 打包流程引入原子写：先写临时文件，成功后再重命名，失败自动清理
- CBZ 命名规则：优先使用画廊 gid 命名（如 `1234567.cbz`），并清理目录内其它旧 .cbz
- 新增/修正本地化字符串（含进度占位），替换硬编码提示

## 主要改动点
### 1) 从 CBZ 读取图片（阅读）
- 位置：`com.hippo.ehviewer.spider.SpiderDen`
- 逻辑：当下载目录中不存在物理图片文件时，自动定位并打开同目录下 `.cbz`，按既有命名规则（`00000001.jpg` 等）匹配 ZipEntry 并流式读取
- 同步改造：`containInDownloadDir` 新增对 `.cbz` 内条目的检测

### 2) 下载页的筛选与批量转换
- 位置：`com.hippo.ehviewer.ui.scene.download.DownloadsScene`
- 菜单：
  - 存储筛选：新增“只看压缩包 / 只看图片”
  - 批量“转换”：可对勾选的下载项执行 图片 → CBZ 或 CBZ → 图片
- 执行：异步后台任务，逐项处理并用 Toast 显示进度（`%d/%d`）与结果

### 3) 高级设置：下载完成后自动打包为 CBZ
- UI 定义：`res/xml/advanced_settings.xml`
- 开关 Key：`auto_cbz_after_download`（`Settings.isAutoCbzAfterDownloadEnabled()` 读取）
- 触发点：`com.hippo.ehviewer.download.DownloadManager` 的下载完成回调（`NotifyTask.run() → TYPE_ON_FINISH`）
- 条件：仅当状态为完成（无缺页）、开关开启、且当前目录不在 CBZ 模式时执行

### 4) CBZ 工具类（核心打包/解包能力）
- 位置：`com.hippo.ehviewer.util.CbzUtils`
- 能力：
  - `isCbzMode(dir)`：判断目录是否为“仅保留一个 .cbz 且无图片”的 CBZ 模式
  - `findCbzFile(dir)`：定位目录中的 `.cbz`
  - `createCbzWithComicInfo(dir, gi, pages, tags, removeImagesAfter)`：
    - 原子写入：`xxx.cbz.tmp` → 成功后 `renameTo(xxx.cbz)`
    - 命名规则：优先 `gid.cbz`，否则回退为 `目录名.cbz`
    - 写入图片与 `ComicInfo.xml`；若 `removeImagesAfter=true`，成功后删除原图片
    - 成功后清理目录内其它旧 `.cbz`，仅保留目标命名的一个包
  - `extractCbz(dir, deleteCbzAfter)`：解包出图片；若 `deleteCbzAfter=true`，成功后删除 `.cbz`
  - `buildComicInfoXml(gi, pages, tags)`：生成基础 ComicInfo.xml 内容（标题、作者/系列、语言、页数、链接、摘要）

### 5) 资源释放与可靠性
- 采用 try-with-resources/`IOUtils.closeQuietly` 确保流关闭
- 打包失败会删除临时 `.tmp`，不会留下半成品 `.cbz`
- 仅在打包成功且 `removeImagesAfter=true` 时删除图片，避免异常导致资源丢失
- 打包单张图片失败会立即中断并记录日志

### 6) 字符串与本地化
- 新增并修正以下键（中/英皆已提供，含进度占位）：
  - `storage_archives_only` / `storage_images_only`
  - `download_convert_storage`, `convert_to_cbz`, `convert_to_images`
  - `convert_in_progress`（含 `%1$d/%2$d`）, `convert_done`（含 `%1$d/%2$d`）, `convert_failed_for`
  - `settings_advanced_auto_cbz_title`, `settings_advanced_auto_cbz_summary`
  - `auto_cbz_failed`（用于替换硬编码 Toast 文案）

## 使用说明
- 阅读：
  - 若目录是 CBZ 模式（仅有一个 `.cbz`，无原图片），阅读器会自动从 `.cbz` 内按既有命名规则读取图片
- 批量转换：
  - 在下载页面，选择多项 → 菜单“转换” → 选择“转换为 CBZ”或“解压为图片”
- 自动打包为 CBZ：
  - 设置 → 高级 → 勾选“下载完成后自动打包为 CBZ”
  - 下载完成后自动生成 `gid.cbz`，写入 ComicInfo.xml，并仅保留 `.cbz`、`.thumb`、`.ehviewer`

## 命名与目录规范
- 打包命名优先采用 `gid.cbz`（例如 `1234567.cbz`），否则回退为 `目录名.cbz`
- 成功打包后会清理目录内其它 `.cbz`，保证同目录仅保留一个压缩包
- 约定目录仅保留：`.cbz`、`.thumb`、`.ehviewer`（与需求一致）

## 回归测试建议
1. 正常下载完成：
   - 开启自动打包 → 目录仅保留 `gid.cbz`、`.thumb`、`.ehviewer`
2. 关闭自动打包：
   - 下载完成不应生成 `.cbz`，仍保留图片
3. 批量转换：
   - 选择若干下载项 → 转换为 CBZ → 阅读可用；再“解压为图片” → 删除 `.cbz`，图片恢复
4. 失败场景：
   - 制造单图读取异常 → `.tmp` 被清理、不留半成品 `.cbz`，原图片未被删除
5. 大页数与特殊文件名：
   - ComicInfo.xml 生成与 Zip 写入应成功

## 已知边界 & 建议
- 若未来引入并行下载，需要确保自动打包不并发写入同一目录（当前一次仅一个任务，安全）
- 可考虑将“解压后是否删除 `.cbz`”变更为设置项
- 可继续完善 ComicInfo.xml 字段（作者、标签映射、发布日期等）
