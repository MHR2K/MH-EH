# 方案 1 实现说明：智能检测 + SMB 直接读取

## 概述

实现了 SMB 路径上 `.thumb` (封面) 和 `.ehviewer` (阅读进度) 文件的读写支持，支持有映射和无映射两种场景。

- `SmbFileHelper.kt` 核心逻辑实现
- `SpiderInfo.java` SMB 进度读写集成
- `ImageBitmapHelper.java` 流类型兼容处理
- 编译和运行时错误修复

⚠️ **已知约束**
- 自动检测依赖 SMB 目录名与本地目录名相同
- SMB 文件操作在后台线程执行，需注意线程安全

## 核心设计

### 1. SMB 文件访问工具类：`SmbFileHelper.kt`

**职责**：统一的 SMB 文件读写接口

**关键方法**：
```kotlin
// 读取 SMB 文件
fun getSmbFileInputStream(
    gid: Long,
    filename: String,
    galleryInfo: GalleryInfo? = null
): InputStreamPipe?

// 写入 SMB 文件
fun writeSmbFile(
    gid: Long,
    filename: String,
    data: ByteArray,
    galleryInfo: GalleryInfo? = null
): Boolean
```

**优先级策略**：
1. **优先**: 检查显式 SMB 映射 (`SmbMappingStore.get(gid)`)
2. **其次**: 尝试自动检测 SMB 路径（与图片文件逻辑一致）
3. **最后**: 返回 null，由调用方降级到本地文件系统

### 2. 封面文件支持：`ThumbDataContainer.kt` 修改

**改动**：
- 在 `get()` 方法中优先尝试从 SMB 读取

- 降级到本地文件系统作为备选方案

**流程**：
```
读取封面:
  1. 尝试从 SMB 读取 (.thumb)
  2. 失败则从本地文件读取
  
保存封面:
  1. 尝试写入到 SMB
  2. 失败则写入到本地文件
```

**流程**：

## 编译错误修复记录

### 错误 1: 未解析的 API 引用

**问题**：编译失败，`Unresolved reference`
```
- EhDB.getSmbServers()
- server.getAuthority(), server.getShare()
- Client.INSTANCE
```

**根本原因**：代码使用了废弃或不存在的 API

**修复方案**：
| 错误代码 | 正确代码 | 说明 |
|---------|---------|------|
| `EhDB.getSmbServers()` | `SmbServerStore.list()` | 使用新的 SMB 服务器存储 API |
| `server.getAuthority()` | `server.authority` | 直接属性访问（Kotlin data class） |
| `server.getShare()` | `server.relativePath` | SMB 路径存储在 relativePath 字段 |
| `Client.INSTANCE.method()` | `Client.method()` | Client 是 object，无需 INSTANCE |
| `entry.isDirectory()` | `entry.isDirectory` | 属性而非方法 |
| `entry.getName()` | `entry.name` | 属性而非方法 |

### 错误 2: Kotlin 对象结构错误

**问题**：编译失败，`Modifier 'companion' is not applicable inside 'standalone object'`

**根本原因**：Kotlin `object` 声明不支持嵌套 `companion object`

**修复方案**：
```kotlin
// ❌ 错误做法
object SmbFileHelper {
    companion object {
        @JvmStatic
        fun getSmbFileInputStream(...) { }
    }
}

// ✅ 正确做法
object SmbFileHelper {
    @JvmStatic
    fun getSmbFileInputStream(...) { }
    
    @JvmStatic
    fun writeSmbFile(...) { }
}
```

**关键**：使用 `@JvmStatic` 注解使方法在 Java 中可作为静态方法调用

### 错误 3: 运行时类型转换异常

**问题**：运行时崩溃，`ClassCastException`
```
com.hippo.ehviewer.smb.Client$openInputStream$1 cannot be cast to java.io.FileInputStream
  at ImageBitmapHelper.java:44 in decode()
```

**根本原因**：
- `ImageBitmapHelper.decode()` 强制将 `InputStream` 转换为 `FileInputStream`
- `SmbFileHelper.getSmbFileInputStream()` 返回自定义 `InputStreamPipe`，其内部流不是 `FileInputStream`

**修复方案**：`ImageBitmapHelper.java` 添加类型检查
```java
InputStream rawIs = isPipe.get();

// 类型检查：只有 FileInputStream 可直接使用
if (rawIs instanceof FileInputStream) {
    fis = (FileInputStream) rawIs;
} else {
    // SMB 或其他自定义流，需要复制到临时文件
    File cacheDir = EhApplication.getInstance().getCacheDir();
    File tempFile = File.createTempFile("image_", ".tmp", cacheDir);
    
    // 复制流到临时文件
    try (OutputStream fos = new FileOutputStream(tempFile)) {
        byte[] buffer = new byte[8192];
        int len;
        while ((len = rawIs.read(buffer)) != -1) {
            fos.write(buffer, 0, len);
        }
    }
    
    // 使用临时文件的 FileInputStream
    fis = new FileInputStream(tempFile);
    tempFile.deleteOnExit();  // 程序退出时删除
}
```

**影响**：修复后能正确加载 SMB 上的缩略图和元数据

## 关键特性

### ✅ 支持有映射的场景

```kotlin
// 用户配置了 SMB 映射
SmbMappingStore.put(gid, SmbMapping(...))

// 直接使用映射路径
val target = Client.Target(mapping.authority, mapping.share, ".thumb")
Client.openInputStream(target)
```

### ✅ 支持无映射的场景

```kotlin
// 没有显式映射，但下载目录在 SMB 上
// 自动检测逻辑：
// 1. 获取本地目录名 (如: "123456-title")
// 2. 扫描 SMB 服务器中同名目录
// 3. 找到后直接访问该目录下的 .thumb / .ehviewer
```

### ✅ 自动降级

```kotlin
// 如果 SMB 访问失败，自动降级到本地文件系统
if (SmbFileHelper.getSmbFileInputStream(...) == null) {
    return localFile.openInputStream()
}
```

### ✅ 双向同步

```kotlin
// 进度修改时：
// 1. 写入到 SMB（同步到服务器）
// 2. 写入到本地（保留本地副本）
// 3. 写入到缓存（UI 立即刷新）
```

## 自动检测算法详解

### 场景
用户在 SMB 服务器上存放了漫画，但没有配置显式映射，只是同步了目录。

### 检测步骤

```
1. 获取本地下载目录名
   localDirName = "123456-title"

2. 获取 SMB 服务器信息
   server = EhDB.getSmbServers().first()
   share = "comics"
   basePath = "/manga"

3. 列出 SMB 共享中的目录
   entries = listDirectory("comics", "/manga")

4. 查找匹配的目录
   for entry in entries:
       if entry.name == "123456-title":
           找到！
           detectedPath = "/manga/123456-title/.thumb"

5. 打开文件
   Client.openInputStream(Target(server, "comics", detectedPath))
```

### 优势
- 透明化：用户无感知
- 灵活性：支持多种存储结构
- 兼容性：文件系统和 SMB 都支持

## 异常处理

### 读取异常

```kotlin
try {
    val pipe = SmbFileHelper.getSmbFileInputStream(...)
    if (pipe != null) {
        return pipe.get()  // 成功
    }
} catch (e: Exception) {
    // 异常时自动降级到本地文件
}
```

### 写入异常

```kotlin
if (SmbFileHelper.writeSmbFile(...)) {
    return true  // SMB 写入成功
} else {
    // SMB 写入失败，降级到本地文件
    localFile.write(data)
}
```

## 性能考虑

### 缓存策略
- `.thumb` 文件由 `Conaco` 图片加载框架缓存
- `.ehviewer` 文件由 `EhApplication.getSpiderInfoCache()` 缓存
- 减少重复读取网络文件

### 异步操作
- SMB 读写在后台线程执行
- UI 线程不阻塞

### 自动检测耗时
- 第一次扫描 SMB 目录时有网络延迟
- 结果缓存在内存中，避免重复扫描

## 常见问题

### Q: 为什么有时候读不到 SMB 上的文件？

A: 可能的原因：
1. SMB 服务器离线或网络不可达
2. 权限不足
3. 自动检测时没有找到匹配的目录名
4. 文件不存在

调试方法：启用 DEBUG 日志查看详细信息

### Q: .ehviewer 文件修改后没有同步到 SMB？

A: 检查：
1. SMB 映射是否配置正确
2. 网络连接是否正常
3. SMB 服务器是否有写权限
4. 本地是否有 `.ehviewer` 文件（作为备选）

### Q: 如何强制使用本地文件而不是 SMB？

A: 临时方案：
1. 禁用 SMB 服务器配置
2. 清除 SMB 映射记录

永久方案：
在 `SmbFileHelper` 中添加开关选项
